# NIRNAY industrial case studies

Seven optimisation models built from public data, one module each in `nirnay/cases/`:

| Case | Module | Class | Rows | Columns (integer) | Nonzeros | Data |
|---|---|---|---|---|---|---|
| Refinery crude selection and blending | `refinery_planning` | LP | 93 | 188 | 726 | US DOE SPR assays, BIS BS-VI specs, PPAC prices, MRPL capacities |
| 12-month refinery production plan | `refinery_multiperiod` | MILP | 1 391 | 2 579 (227) | 9 721 | as above + PPAC monthly consumption |
| Thermal unit commitment | `unit_commitment` | MILP | 39 395 | 44 544 (16 128) | 167 806 | PGLib-UC, RTS-GMLC |
| Economic dispatch with DC network | `economic_dispatch` | QP | 9 266 | 5 871 | 25 669 (Q: 122) | PGLib-OPF case2000_goc |
| Capacitated facility location | `facility_location` | MILP | 101 100 | 100 100 (100) | 400 100 | OR-Library capb |
| Indian MS/HSD distribution | `product_distribution` | LP | 114 | 1 512 | 3 024 | PPAC 2024-25, Wikidata |
| Crude-oil unloading and blending schedule | `crude_scheduling` | MILP | 2 470 | 1 848 (112) | 17 748 | Lee et al. 1996 via minlp.org |

Usage:

```python
from nirnay.cases import build, info
model = build("unit_commitment")          # a nirnay.Model
info("unit_commitment")["sources"]        # URLs and licences
```

Every module has a `CASE_INFO` dict with the title, sector, problem class, the sources (URL and
licence of each) and two lists: what is taken from the sources unchanged (`real`) and what is
assumed (`assumed`). Each assumption also appears in the section below and next to the parameter
in the code.

Files:

* `data/cases/<case>.mps` is the default instance of each case, written by `nirnay.io.mps_write`.
* `data/cases/reference.csv` holds the HiGHS 1.15.1 result for each file: status, objective, MIP
  gap and bound, and solve time. It is regenerated by `python bench/case_reference.py`, which
  builds each case, writes the MPS file and solves that file with HiGHS.
* `data/cases/raw/` holds the downloaded source files. It holds only files that may be
  redistributed. The BIS standard PDFs (licensed copies from the BIS portal) and the BP assays
  (whose notice forbids redistribution) were deliberately left out; the BIS standards are cited
  through their public copies on archive.org.
* `tests/test_cases.py` builds every case, validates it, checks that the MPS file matches the
  build, and re-solves the MPS file with HiGHS against `reference.csv`. Solves slower than a
  minute run only with `NIRNAY_SLOW=1`.

Units: kt = thousand tonnes; k$ = thousand US dollars. Objective values are in the sense of the
file (the refinery cases are written as cost minimisation, so their objectives are negative
margins).

The HiGHS results table is at the end of this document.

## 1. Refinery crude selection and product blending (LP) - `refinery_planning`

**Decision.** For one year of operation, choose how much of each crude to run on each of MRPL's
three crude distillation units, where each distillation cut goes (reformer, fluid catalytic
cracker, product pools, naphtha or fuel oil sales), and how to blend BS-VI petrol (MS 91, MS 95),
BS-VI diesel (HSD), jet fuel (ATF), LPG, naphtha and fuel oil to Indian specifications, to
maximise gross margin (product value minus crude cost).

**Formulation.** Indices: crude c, CDU u, cut s in {LPG, LN, HN, KERO, GO, VGO, VR}, product p.
Every cut of every crude is its own stream with the assay's properties, so no pooling
bilinearity arises.

    x[c,u] >= 0                              crude c charged to CDU u (kt/yr)
    f[c,s,d] >= 0                            cut s of crude c sent to destination d
    sum_c x[c,u] <= Cap[u]                                   CDU capacity
    sum_d f[c,s,d] = y[c,s] * sum_u x[c,u]                   cut yields (mass fractions)
    reformate = 0.90 R,  butane = 0.02 R                     R = heavy naphtha to reformer
    FCC severity k: butane, cracked naphtha, cracked distillate = yield[k] * F[k]
    for each product pool P with components i (mass m_i, density rho_i):
      density:   rho_lo * sum m_i/rho_i <= sum m_i <= rho_hi * sum m_i/rho_i
      RON:       sum (m_i/rho_i) (RON_i - RON_min) >= 0            (MS 91, MS 95)
      cetane:    sum (m_i/rho_i) (CI_i - 46) >= 0                  (HSD)
      smoke:     sum (m_i/rho_i) (SP_i - SP_min) >= 0              (ATF)
      naphth.:   sum (m_i/rho_i) (N_i - 3.00) <= 0                 (ATF route B)
      sulphur:   sum m_i (S_i - 0.30) <= 0                          (ATF, mass %)
      sales of MS 91, MS 95, HSD, ATF, LPG <= market limit
    minimise  crude price * sum_c bbl(x_c) - sum_P value(P)

Products priced in $/bbl (MS, HSD, ATF) are valued by volume, `m_i / (rho_i * 0.158987)` barrels,
which is linear in the mass flows. IS 1571 allows two ways to certify jet fuel (smoke point
>= 25.0 mm, or smoke point >= 18.0 mm with naphthalenes <= 3.00 % v/v). They are modelled as two
pools, ATF_A and ATF_B, that share the ATF market limit.

**Size.** 93 rows, 188 columns, 726 nonzeros with the default 8 crudes. The real planning problem
at this level of aggregation (a single annual period, one refinery) is this size. The
multi-period case below is the larger version.

**Assumptions** (also in `CASE_INFO["assumed"]`):
* All crudes are priced at the Indian basket average, because grade differentials are not public.
  As a result the model prefers the crudes with the best yields.
* ATF is valued at PPAC's kerosene FOB quote.
* Conversion-unit yields come from the FAWLEY example refinery, not from MRPL, whose unit yields
  are not public. They are applied to every crude's heavy naphtha and vacuum gas oil.
* Hydrotreaters are not modelled. MS and HSD components are assumed treated to 10 mg/kg sulphur
  with no change in mass, density, RON or cetane index.
* Reformer and FCC capacities are not public and are left unbounded. Refinery fuel has no value
  and operating costs are omitted.
* RON, cetane index, smoke point and naphthalenes blend linearly by volume. ATF freezing point
  (max -47 C) is not modelled because it does not blend linearly.
* Fuel oil has no sulphur limit (IS 1593 is available only as a scanned image).
* Assay cut yields are normalised to 100 % by mass. The ExxonMobil files add up to between
  100.05 % and 100.73 %.

## 2. Twelve-month refinery production plan (MILP) - `refinery_multiperiod`

**Decision.** Plan April 2024 to March 2025 month by month: which crude parcels to buy, how to run
the units, how much MS, HSD and ATF to hold in storage ahead of seasonal demand, and which FCC
severity to run each month, with a limit on severity changes.

**Formulation.** Month t = 1..12 contains a copy of the section 1 network, with CDU capacity scaled
by days in the month. On top of it:

    n[c,t] integer >= 0          parcels of crude c bought in month t (processed that month)
    sum_u x[c,u,t] = parcel_kt[c] * n[c,t],   parcel_kt[c] = 1000 kbbl * 0.158987 * rho_c
    n[c,t] <= N_max * w[c,t],  sum_c w[c,t] <= 3,  w binary            (tank segregation)
    I[p,t] = I[p,t-1] + production[p,t] - sales[p,t],  I[p,0] = I[p,12] = 0   (MS91, MS95, HSD, ATF)
    sum_p I[p,t] / rho_min[p] <= 81 thousand m3                         (finished-product storage)
    sales[p,t] <= MRPL output[p] * India consumption[p,t] / India total[p]
    F[k,t] <= Fmax * y[k,t],  y[low,t] + y[high,t] <= 1                 (one FCC severity)
    z[t] >= y[k,t] - y[k,t-1],  sum_t z[t] <= 2                          (severity changeovers)
    minimise  78.56 $/bbl * 1000 kbbl * sum n[c,t] - product value

Revenue is booked at production. Prices are constant over the year and closing stock is zero, so
this equals revenue at sale.

**Size.** 1 391 rows, 2 579 columns (96 integer parcel counts, 131 binaries), 9 721 nonzeros.

**Data provenance.** Everything in section 1, plus:

| Parameter | Values | Source | Licence |
|---|---|---|---|
| All-India monthly consumption, FY 2024-25 | MS 3149-3512, HSD 6369-8412, ATF 707-801, LPG 2320-2835 kt/month | PPAC, Consumption of petroleum products (Annexure-I, April-24 to March-25), https://ppac.gov.in/consumption/products-wise | GODL |
| Finished-product storage | 81 thousand kL | MRPL Annual Report 2024-25 (Devangonthi terminal), URL as in section 1 | public |
| Crude bought as Suezmax parcels and co-loaded into VLCCs | qualitative | MRPL Annual Report 2024-25, risk table p. 28-29 | public |
| Days per month | 30/31/28 | calendar, FY 2024-25 | - |

**Assumptions.** All of section 1, plus: the monthly market limit is MRPL's annual output
multiplied by the national monthly share. The parcel size is 1 million barrels (the annual report
confirms Suezmax parcels but not their size), and each parcel is processed in its month (no crude
tank inventory). At most 3 crudes per month and at most 2 FCC severity changes per year. The
81 thousand kL terminal storage is used as the finished-product storage limit, with product volume
at the minimum specification density. There is no holding cost.

## 3. Thermal unit commitment (MILP) - `unit_commitment`

**Decision.** Hourly on/off status, start-up type and output of the 73 thermal units of the
RTS-GMLC system over 48 hours. The dispatch uses renewable output within availability, meets
demand exactly and meets the spinning-reserve requirement.

**Formulation.** The reference model published with PGLib-UC (`MODEL.tex`, `uc_model.py`,
equations 1-24): the tight and compact formulation of Morales-Espana, Latorre and Ramos (2013)
with the piecewise production cost of Sridhar, Linderoth and Luedtke (2013). Variables per unit g
and hour t: u, v, w (on, start, stop; binary), delta[s] (start-up category; binary), p (output
above minimum), r (reserve), c (cost above minimum), lambda[l] (piecewise weights).

    min  sum_g sum_t c[g,t] + CP1_g u[g,t] + sum_s CS_g^s delta_g^s(t)                    (1)
    sum_g (p[g,t] + Pmin_g u[g,t]) + sum_w pw[w,t] = D(t);   sum_g r[g,t] >= R(t)         (2,3)
    initial up/down time, logical, start-up category and ramp conditions at t = 1        (4-10)
    u >= must_run;  u[t] - u[t-1] = v[t] - w[t]                                          (11,12)
    sum_{i=t-UT+1..t} v[g,i] <= u[g,t];  sum_{i=t-DT+1..t} w[g,i] <= 1 - u[g,t]          (13,14)
    delta_s(t) <= sum_{i=TS_s..TS_{s+1}-1} w(t-i);  v = sum_s delta_s                     (15,16)
    p + r <= (Pmax-Pmin) u - max(Pmax-SU,0) v;  p + r <= (Pmax-Pmin) u - max(Pmax-SD,0) w[t+1]   (17,18)
    p[t] + r[t] - p[t-1] <= RU;  p[t-1] - p[t] <= RD                                     (19,20)
    p = sum_l (P_l - P_1) lambda_l;  c = sum_l (CP_l - CP_1) lambda_l;  u = sum_l lambda_l     (21-23)
    Pmin_w(t) <= pw[w,t] <= Pmax_w(t)                                                    (24)

**Size.** 39 395 rows, 44 544 columns (16 128 binary), 167 806 nonzeros (73 thermal units, 81
renewable units, 48 hours).

**Data provenance.**

| Parameter | Values | Source | Licence |
|---|---|---|---|
| Demand, reserves, 73 thermal units (limits, ramps, min up/down, piecewise costs, 3 start-up categories, initial state), 81 renewable availability profiles | 48 hourly periods | PGLib-UC `rts_gmlc/2020-01-27.json`, https://raw.githubusercontent.com/power-grid-lib/pglib-uc/master/rts_gmlc/2020-01-27.json | CC BY 4.0 |
| Formulation | eq. (1)-(24) | https://github.com/power-grid-lib/pglib-uc/blob/master/uc_model.py; Morales-Espana et al., https://doi.org/10.1109/TPWRS.2013.2251373; Sridhar et al., https://doi.org/10.1016/j.orl.2013.08.010 | CC BY 4.0 / citation |
| Underlying system | | RTS-GMLC, https://github.com/GridMod/RTS-GMLC | see repository |

**Assumptions.** None in the data. **Known limitation:** the reference value is solved to a 1 %
relative MIP gap, the setting of pglib-uc's own reference script (`mipgap 0.01`). With a 1e-6 gap
target, HiGHS 1.15.1 stalled at a 0.52 % gap after 600 s (incumbent 1 232 940.11). The value in
`reference.csv` is therefore a 1 %-optimal solution, not a proven optimum, and the test compares
against it with a 1 % tolerance.

## 4. Economic dispatch with DC network constraints (QP) - `economic_dispatch`

**Decision.** Output of each generator in a 2000-bus grid for one operating snapshot, at least
total quadratic generation cost, subject to bus power balance, DC power flow, line thermal limits
and angle-difference limits.

**Formulation** (the DC model of PowerModels.jl, which produced the DC column of pglib-opf's
BASELINE.md):

    min  sum_g c2_g pg_g^2 + c1_g pg_g + c0_g                           ($/h)
    sum_{g at i} pg_g - sum_{l from i} f_l + sum_{l to i} f_l = Pd_i + Gs_i      every bus i
    f_l = baseMVA * b_l * (theta_from - theta_to - shift_l),   b_l = x_l / (r_l^2 + x_l^2)
    -rateA_l <= f_l <= rateA_l;   angmin_l <= theta_from - theta_to <= angmax_l
    Pmin_g <= pg_g <= Pmax_g;   theta_ref = 0

Tap ratios are ignored, as in PowerModels' DC model. Q is diagonal (2 c2 on each generator
column).

**Size.** 9 266 rows, 5 871 columns (2000 bus angles, generators in service, 3639 branch flows),
25 669 nonzeros, 122 nonzeros in Q.

**Check against a published value.** The HiGHS optimum 943 042.2 $/h matches the DC objective
9.4304e+05 $/h that pglib-opf publishes for this case (BASELINE.md, PowerModels.jl v0.19.9).

**Data provenance.**

| Parameter | Values | Source | Licence |
|---|---|---|---|
| Bus loads, shunts, generator limits, quadratic cost coefficients, branch r, x, rateA, angle limits, phase shifts | 2000 buses, 3639 branches | PGLib-OPF v23.07 `pglib_opf_case2000_goc.m`, https://raw.githubusercontent.com/power-grid-lib/pglib-opf/master/pglib_opf_case2000_goc.m | CC BY 4.0 |
| Published DC-OPF objective | 9.4304e+05 $/h | https://github.com/power-grid-lib/pglib-opf/blob/master/BASELINE.md | CC BY 4.0 |
| Network origin | synthetic Texas-footprint grid | Birchfield et al. 2017, https://doi.org/10.1109/TPWRS.2016.2616385 | citation |

**Assumptions.** The DC power-flow approximation (lossless, flat voltage), the standard model for
economic dispatch, and a single period, because the file is one snapshot. The PGLib-UC instance of
section 3 has only piecewise-linear costs, so the quadratic-cost dispatch uses PGLib-OPF, the
sister library of the same IEEE PES task force.

## 5. Capacitated facility location (MILP) - `facility_location`

**Decision.** Which of 100 candidate depots to open (fixed cost, capacity) and how to split each
of 1000 customers' demand among open depots, at least fixed plus allocation cost. This is the core
decision in designing a product depot and terminal network.

**Formulation.**

    min  sum_i f_i y_i + sum_ij c_ij x_ij
    sum_i x_ij = 1                    every customer j   (x_ij = fraction of demand from depot i)
    sum_j d_j x_ij <= s_i y_i         every depot i
    x_ij <= y_i                       every pair (strong linking; valid and tightens the LP)
    0 <= x_ij,  y_i binary

c_ij is, as in the data files, the cost of serving all of customer j's demand from depot i.

**Size.** 101 100 rows, 100 100 columns (100 binary), 400 100 nonzeros (instance capb with depot
capacity 5000).

**Check against a published value.** HiGHS proves 13 656 379.5776, equal to OR-Library's published
optimum 13656379.578 for capb (capacity 5000). The smaller instances cap41 (1 040 444.375) and
cap131 (793 439.562) also reproduce their published optima.

**Data provenance.**

| Parameter | Values | Source | Licence |
|---|---|---|---|
| Capacities, fixed costs, demands, allocation costs | 100 x 1000 | OR-Library capb, https://people.brunel.ac.uk/~mastjjb/jeb/orlib/files/capb.txt | MIT (https://people.brunel.ac.uk/~mastjjb/jeb/orlib/legal.html) |
| Capacity value 5000, published optimum | | https://people.brunel.ac.uk/~mastjjb/jeb/orlib/files/capopt.txt | MIT |
| Problem definition | | J.E. Beasley, EJOR 33 (1988) 314-325, https://doi.org/10.1016/0377-2217(88)90175-0 | citation |

**Assumptions.** The data are a standard benchmark, not an Indian network, because no Indian
depot-level dataset with costs and capacities is public. `build("capa", 8000)` gives the harder
capa instance: HiGHS finds its published optimum 19 240 822.449 but does not close the gap within
30 minutes.

## 6. Distribution of BS-VI petrol and diesel across India (LP) - `product_distribution`

**Decision.** How much BS-VI MS and HSD each of 21 Indian refineries sends to each of 36 states and
union territories, so that every state's 2024-25 sales are met with the least transport work
(tonne-km).

**Formulation.**

    min  sum_{p,r,s} dist(r,s) x[p,r,s]
    sum_s x[p,r,s] <= supply[p,r]        every product, refinery
    sum_r x[p,r,s]  = demand[p,s]        every product, state
    x >= 0

**Size.** 114 rows, 1 512 columns, 3 024 nonzeros.

**Data provenance.**

| Parameter | Values | Source | Licence |
|---|---|---|---|
| State-wise MS and HSD sales 2024-25 | MS 1.5-4833 kt, HSD 21-10636 kt per state; totals 40 004.5 and 91 365.4 kt | PPAC, https://ppac.gov.in/uploads/page-images/1787137273_Statewise_Sales-POL_Consumption_Final.xlsx (sheets PT_Cons_Statewise MS / HSD) | GODL |
| Refinery-wise crude processed 2024-25 | 73.8 kt (Tatipaka) to 34 990.5 kt (RIL Jamnagar DTA) | PPAC, Crude oil processed by refineries, FY 2024-25 (P), https://ppac.gov.in/production/crude-processing | GODL |
| All-India production MS-VI 42 178.97 kt, HSD-VI 92 170.41 kt | | PPAC, Production of petroleum products 2024-25 (P), https://ppac.gov.in/production/petroleum-products | GODL |
| Coordinates of refineries and state capitals | | Wikidata (SPARQL results in `data/cases/raw/supply/wikidata_*.json`), https://query.wikidata.org/ ; Wikipedia (Koyali, Jamnagar, Tatipaka, Kochi infobox), https://en.wikipedia.org/wiki/Kochi_Refinery | CC0; CC BY-SA 4.0 |

**Assumptions.**
* PPAC does not publish refinery-wise product output. Each refinery's MS-VI and HSD-VI supply is
  therefore the national production times its share of crude processed. RIL's export-oriented SEZ
  refinery and CPCL Narimanam (zero throughput) are excluded.
* Cost is great-circle distance to the state capital. No machine-readable public freight tariff
  was found: the Indian Railways rate circular that was downloaded is a scanned image. Real rail,
  pipeline and road distances are longer.
* HPCL Mumbai is placed at the adjacent BPCL Mahul coordinates, and HPCL Visakh at Visakhapatnam
  city.
* Imports, exports and inventories are not modelled.

## 7. Crude-oil unloading, blending and CDU charging schedule (MILP) - `crude_scheduling`

**Decision.** Over a 10-day horizon (COSP2): when and how much to unload from three arriving
vessels into three storage tanks, when to transfer crude to three charging tanks, and which tank
feeds each of two CDUs, so that CDU feeds meet two property specifications (e.g. sulphur) and
demand, CDUs run continuously, and the gross margin of distilled crude is maximised.

**Formulation.** MOSMILP from `Scheduler.gms` (minlp.org problem 117): the Multi-Operation
Sequencing priority-slot model of Mouret, Grossmann and Pestiaux (2009) without the bilinear
composition equality, which is the MILP relaxation that forms the first step of the authors'
two-step method. Slots i = 1..n, operations v, crudes p, tanks r:

    max  sum val(v,p) VP[i,v,p]
    sum_{v in clique} Z[i,v] <= 1;  cardinality bounds on each operation set; first-slot bounds
    vessels unload in arrival order (time and slot-count precedence)
    E = S + D;  S >= minS Z;  E <= H Z;  minVT Z <= VT <= maxVT Z;  VT = sum_p VP
    LT[i,r] = L0 + sum_{j<i} (in - out);  LP[i,r,p] likewise;  LT = sum_p LP;  tank bounds
    minFR D <= VT <= maxFR D;  sum of CDU durations = H;  demand per charging tank
    min/max property:  xmin VT <= sum_p x_p VP <= xmax VT
    end-of-horizon level bounds;  clique non-overlap (big-M);  symmetry breaking

**Size.** Default COSP2 with n = 8 slots: 2 470 rows, 1 848 columns (112 binary), 17 748
nonzeros. `build(instance, slots)` gives any of COSP1-4.

**Check against published values.** All four instances reproduce Table 1 of the published session
results: COSP1 79.750 (n = 5), COSP2 101.175 (n = 6, 8), COSP3 87.400 (n = 5), COSP4 132.548
(n = 4). The column counts equal Table 3 minus GAMS's objective variable: 535, 1 386, 1 280 and
1 564 against the published 536, 1 387, 1 281 and 1 565.

**Data provenance.**

## MPS export and round trip

`nirnay.io.mps_write.write_mps(model, path)` writes free-format MPS with OBJSENSE, integer
MARKER blocks, RANGES for ranged rows (with the side and range chosen so the reader rebuilds both
bounds bit for bit), every bound type (FR, MI, PL, BV, LO, UP, FX), the objective constant as the
RHS of the objective row, and QUADOBJ (lower triangle) for Q.

Round-trip check on all 154 files in `data/netlib` and `data/miplib`: read_mps, then write_mps,
then read_mps.

* All 154 files give identical arrays (c, c0, sense, bounds, row bounds, integrality, CSC pattern
  and values). 153 also keep their row and column names; netlib `forplan` has fixed-format names
  containing spaces, which free MPS cannot hold, so the writer replaces its names by generated
  ones (`R0000`, `C0000`, ...).
* HiGHS reads the original (decompressed) and the written file into identical models for all 154
  files, after sorting matrix entries within each column: HiGHS keeps file order within a column,
  and the writer emits rows in sorted order.
* All 90 netlib LPs and 50 of the 64 MIPLIB instances solve to optimality within 120 s with the
  same status and objective, identical or within 1e-9 relative.
* The other 14 MIPLIB instances (arki001, dano3mip, danoint, fast0507, markshare1/2, mas74, mas76,
  mkc, noswot, nw04, pk1, qiu, seymour, swath) stop at the time limit for both files. Eleven stop
  with identical incumbents. dano3mip, mkc and swath stop with different incumbents, because the
  within-column entry order differs and the search path changes with it; the models are
  identical.
